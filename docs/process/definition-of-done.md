# Acceptance and evidence

## Design decisions

Record the selected option, the tradeoff, the issue and affected documents. A comparison alone is unfinished if later tasks still cannot tell which behavior to implement.

## Runtime changes

Provide the Godot version, reproduction steps and relevant test or playtest results. Verify the intended behavior and its failure path. Shared-state changes need two-client evidence; persistence changes need save/load and interruption checks. Add coverage when it protects behavior rather than repeating implementation details.

## Art and content

Check representative poses, customization combinations, readability and import behavior. Record authorship and rights. A story event needs a playable or inspectable path through each supported outcome, including a failure or interruption where relevant.

## Release readiness

Link the exact candidate commit, builds, acceptance evidence and known issues. A checklist item is complete only when someone can inspect what supports it. Closing an epic or milestone does not by itself pass the associated release gate.
